# SPK-05 Server service control script, runtime environment and script test harness
Owner: mivo-synology
Depends on: SPK-01
Files/areas: `packaging/synology/package/scripts/start-stop-status`,
`packaging/synology/package/scripts/common.sh`, `packaging/synology/package/scripts/package.env`
(template), `packaging/synology/test/**` (new: harness, fake server, tests, `README.md`)

## Goal
Package Center can start, stop and query the media server (the `mivo` binary running as a DSM
service on port 8460) reliably: the server gets the DSM paths of
ADR 0026 §6, a failed start is reported instead of shown as "running", and a stop gives the
server its graceful shutdown time.

## Acceptance criteria
- [ ] `common.sh` loads `package.env` (brand values) and derives every path of ADR 0026 §6 from the
      `SYNOPKG_*` variables (names per SPK-01); it exports `<ENV_PREFIX>_CONFIG_DIR`,
      `_PATHS_DATA`, `_PATHS_CACHE`, `_PATHS_TRANSCODE`, `_TOOLS_FFMPEG`, `_TOOLS_FFPROBE` and
      `HOME` (if DSM provides a home), built from `ENV_PREFIX`, never a literal prefix.
- [ ] `start-stop-status start`: creates the data, cache and transcode directories (0750) if
      missing; rotates `<id>.log` to `<id>.log.1` when it is larger than 10 MiB (named constant);
      starts `$SYNOPKG_PKGDEST/bin/<id>` in the background with stdout and stderr appended to the
      log; writes the PID file; exits 0 once `<id> healthcheck` succeeds (polled, named interval).
      If the process exits first it exits 1 within the start budget and writes the last 20 log
      lines to `$SYNOPKG_TEMP_LOGFILE` when that is set. Alive but not healthy after 30 s → 0.
      Already running → 0 without a second process.
- [ ] `stop`: `SIGTERM`, waits up to 20 s (named constant), then `SIGKILL`; removes the PID file;
      exits 0, also when nothing runs.
- [ ] `status`: 0 when the PID file names a live process whose `/proc/<pid>/exe` is the package
      binary; 3 when not running, removing a stale PID file (dead process or a PID reused by
      another program); 150 when the binary is missing or not executable. Other arguments → 1
      with a usage line on stderr.
- [ ] Brand-free: `rg -i mivo packaging/synology/package` finds nothing; the test fixture
      `package.env` uses a different brand (e.g. `ID=demo`, `ENV_PREFIX=DEMO`) and the tests
      assert `DEMO_CONFIG_DIR` etc. reach the fake server.
- [ ] Test harness: a fake server (sh script) that records its arguments and environment, can be
      told to become healthy, stay unhealthy, exit early, or ignore `SIGTERM`; `healthcheck`
      answers from a control file. Tests run every case under busybox `sh` and `bash` (DSM's
      shell per SPK-01): start healthy, start with early exit (exit 1 + log tail), slow start,
      double start, graceful stop, stop that needs `SIGKILL` (shortened timeout through a
      test-only variable documented in the script), stale PID, missing binary (150), log
      rotation.
- [ ] One documented command runs all script tests in Docker, e.g.
      `docker run --rm -v "${PWD}:/code" -w /code bats/bats:<pinned tag> packaging/synology/test/scripts`,
      and passes on the Windows dev machine (Docker Desktop).
- [ ] `docker run --rm -v "${PWD}:/mnt" -w /mnt koalaman/shellcheck:<pinned tag> -s sh packaging/synology/package/scripts/start-stop-status packaging/synology/package/scripts/common.sh`
      → no findings.
- [ ] Gates: shellcheck + script tests green; Go gates unaffected.

## Notes
- POSIX `sh` only, `set -eu`, every expansion quoted; no `pidof`/`pgrep` dependency (read
  `/proc`). The scripts run as the package user, never `sudo`.
- `package.env` is generated by SPK-03 and staged by SPK-14; the repository file is a fixture-like
  template with build tokens; the tests use their own fixture. Where `package.env` and `common.sh` live in the SPK follows SPK-01 Q5 (`scripts/` if
  DSM allows extra files there).
- Do not set `server.port`, `server.lan_only` or libraries through the environment: they stay in
  `config.yaml` (ADR 0026 §6).
- Line endings: the files must keep LF on Windows checkouts (`.gitattributes` already forces LF;
  the test harness fails on CR).
- The health probe reads the same environment, so `healthcheck` must run after `common.sh` has
  exported it.
